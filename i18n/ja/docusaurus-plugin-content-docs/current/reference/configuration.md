# 構成とコンテキスト {/* #configuration-and-context */}

この参照は、プロジェクトコンテキスト、新しいセッションのデフォルトと既存のセッションの構成を分離します。 [プロジェクト](../guides/projects.md) または [プロバイダーのセットアップ](../guides/providers.md) を使用して、対応するインターフェイスのウォークスルーを使用します。

## コンテキストと構成の所有権 {/* #context-and-configuration-ownership */}

| 値 | 所有者と効果 | 交換しない |
| --- | --- | --- |
| プロジェクト **Name** | プロジェクト表示名、必須、200文字の最大文字 | ユニークなプロジェクトID |
| プロジェクト **Description** | プロジェクトリストの説明、1,000 文字の最大値。 エージェントのプロンプトに含まれていない | エージェントの指示 |
| プロジェクト **Agent Context** | 最大 16,000 文字; 新規および再開されたプロジェクトセッションに含まれており、モデルプロバイダに送信 | クレデンシャルまたは実行されたタスクリクエスト |
| セッション **Title** | タイトルを表示, 最大 80 文字 | プロジェクトコンテキストまたはブランチ識別子 |
| セッション **Description** | 組織の説明、最大 1,000 文字 | 新規ユーザーメッセージ |
| モデルプロバイダー | 接続、アカウントおよび構成されたモデルカタログ | エージェントフレームワークのインストール |
| エージェントフレームワーク | タスクを実行するために使用されるランタイム | Notebook通訳者 |
| Python/Rランタイム | Notebook実行に使用される通訳者 | モデルまたはその推論努力の設定 |
| メモリ | 独自のスコープとリコールコントロールでメモを保存 | 完全な会話履歴 |
| スキル | 再利用可能な方法の指示とファイル | 既にインストールされている依存性または許可されたサービス資格 |

## 高度な: タスク API 構成 {/* #advanced-task-api-configuration */}

### タスクAPIで作成した新しいセッション {/* #new-sessions-created-through-the-task-api */}

タスクランナーは各フィールドを別々に解決します。 以下の優先事項は、**新規登録** タスク API セッションに適用され、既存のデスクトップの会話に反しては適用されません。

| フィールド | 決断、最優先の第一優先 |
| --- | --- |
| パーミッションプロファイル | Explicit 実行リクエスト → プロジェクトセッションのデフォルト → アプリケーションデフォルト → `ask` |
| 自動レビュー | Explicit リクエスト → プロジェクトデフォルト → `false` |
| メモリの有効化 | Explicit リクエスト → プロジェクトデフォルト → `true` |
| 委任方針 | Explicit リクエスト → プロジェクトデフォルト → `allow` |
| スペシャリスト | 設定時に明示的なリクエスト → プロジェクトデフォルト |
| プロバイダー/モデル/リーソン | プロジェクトの構成上の明示的な構成パッチ、または有効なapp/provider構成 |
| 選択されたコンピュートホスト | 選択したIDの有効期限 → プロジェクト選択したID |

Compute Host は、新しいセッションの準備中に選択した ID も組み込まれています。 明示的に空の enabled-host リストは、選択したホストが含まれている前に、継承された有効なリストをクリアします。 既存のセッション構成の更新には、選択したすべての ID が有効なセットに存在する必要があります。

[CLI](cli.md) または [タスク SDK/API](api.md) 参照を実際の読み込み/更新コマンドで使用します。 プロジェクトセッションのデフォルトは、設定契約です。 プロジェクト名/説明ダイアログがこれらのすべてのフィールドを公開すると仮定しません。

### 設定値の受け入れ {/* #accepted-configuration-values */}

| フィールド | 受け入れられた値 |
| --- | --- |
| `agentConfiguration.providerId` | 非empty 設定プロバイダ ID |
| `agentConfiguration.model` | 任意モデルID; 更新パッチを使うと、 `null` プロバイダのデフォルトにリセットする |
| `agentConfiguration.reasoningEffort` | `default`, `low`, `medium`, `high`, `xhigh`, `max`; 実際の選択性はプロバイダ/モデルに依存します |
| `permissionProfile` | `ask`, `auto`, `full` |
| `autoReviewEnabled` | ボオラン |
| `memoryEnabled` | ボオラン |
| `delegationPolicy` | `allow`, `deny` |
| `specialistId` プロジェクトのデフォルトで | 不在ID; 通常のセッション構成パッチのフィールドではない |
| `computeHosts.enabled`, `.selected` | 非空のホスト ID の配列; 選択されたサブセットが有効になっている必要があります。 |

スキーマは未知のフィールドを拒否します。 表示されるモデルのプレゼンスは、現在のフレームワークや資格情報で選択可能であることを保証するものではありません。 構成されたカタログおよび可用性の結果を使用して下さい。

### プロバイダのデフォルトと未利用可能な設定 {/* #provider-defaults-and-unavailable-configurations */}

サブスクリプションプロバイダの場合、モデルを未指定のままにして、アカウント/CLI 所有のデフォルトを保存します。 カタログにリストされている最初のモデルをピン留めしません。 保存されたセッション構成が選択できなくなった場合、レンダラリゾルバは、アクティブな選択可能なアプリ設定を使用できます。 利用できない場合は、利用できません。 プロバイダーを変更した後、古い作業を再開する際に選択したモデルを調べます。

### ルールの更新と再開 {/* #update-and-resume-rules */}

編集する前に、既存のセッションの現在の設定をお読みください。 **`expectedRevision`**、非負の整数、アップデートを含む。 サーバは、`session_revision_conflict` として古いリビジョンを拒否します。 また、セッションが活発な仕事をしている間、またはidle/error状態外にいる間、更新を拒否します。

プロバイダーの変更は、明示的なモデルまたは`model: null`のいずれかで、新しいプロバイダのデフォルトを選択します。 プロバイダーの変更中にモデルを省略しても、古いプロバイダのモデルをサイレントに持ちません。 モデルリセットは空の文字列とは異なる。

既存のタスクAPIセッションを再開する前に、プロバイダ、モデル、推論努力、メモリ、または有効化したコンピュートホストを変更するには、セッション構成の更新操作を最初に使用してください。 履歴書のリクエストでこれらの作成時間フィールドが `invalid_request` を返すようにしました。 作業ディレクトリは、セッションのcanonicalディレクトリに引き続きマッチしなければなりません。

プロジェクトのデフォルト更新は、現在のプロジェクトから正の整数タイムスタンプである **`expectedUpdatedAt`** とパッチを使用します。 `null`プロジェクトデフォルトフィールドは、そのオーバーライドを削除します。 フィールドを省略すると、そのフィールドが保存されます。 デフォルトの更新は、将来のセッションの作成を管理し、既存の出力証拠を刷新しません。

## ホストの指示と秘密保存の選択肢 {/* #host-instructions-and-secret-storage-choices */}

保存されたコンピュートホストの指示と検出されたリソースは別々です。 空の保存された指示文書は、成功したリソースプローブとは異なる。 エージェントアシスト交換は、現在の保存テキストをガードとして使用しなければなりません。 [ホストの詳細](../guides/remote-compute.md#keep-host-instructions-separate-from-detected-resources) を参照してください。 この内部契約は、公開タスクAPIとは別々です。

クレデンシャルストレージは、プロジェクト/セッションの好みではなく、スタートアップの選択です。 スコープ、OS-store のデフォルトとマイグレーションの制限については、[Linuxファイルモード](server.md#credential-storage-on-headless-linux) を参照してください。 セッション設定のJSONにクレデンシャルストアのフラグを置かないでください。

## 関連する境界 {/* #related-boundaries */}

承認範囲および方針の発注のために、[権限](permissions.md)を使用します。 ポータブルSkill/Specialist/Connectorのドキュメントでは、[パッケージのフォーマット](packages.md)を使用します。 パッケージのエクスポートは、セッションの構成または保存されたアカウントの秘密のダンプではありません。 デスクトップセッションとローカルWebサービスの違いについては、[ヘッドレスサービス](server.md)を使用します。
