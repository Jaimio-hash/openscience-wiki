# タスクの委派と Side Chat {/* #delegation-and-side-chat */}

Side Chat を使用して、現在のタスクに沿って質問を議論したり、別のエージェントに別のタスクを与えるための委任を行います。 異なる方向に完全な会話を続けるために、 [セッションの分岐](sessions.md). . . .

## Side Chat {/* #side-chat-availability */}

### 利用場面 {/* #when-to-use-it */}

Side Chat を開き、分析結果の用語を説明し、二つのアプローチを比較したり、レポートを単語する方法を議論したりします。 ディスカッションの後、メインの会話、Mainに選択したアドバイスを送信します。

### 使い方 {/* #how-to-use-it */}

1. 既存のセッションでは、送信ボタンの横に**More send options → Side chat**を開きます。 空のComposerで開くことができます。新しいSide Chatドラフトがすぐに現れます。 そこに質問を書いて、モデルと推論の努力を確かめ、それからそれを送って下さい。
2. 独立した**Side chat**プレビュータブで回答を読む。 **Side chat follow up** を使って質問をしましょう。 Mainを継続しながら、同じセッションで複数のサイドディスカッションを続け、タブ間で切り替えることができます。
3. Mainでアドバイスを共有するには、Side Chatを明示的に依頼して、それを中継します。 例えば、「このアドバイスをMainに送る:レポートの別の部分で欠損値処理を記述する」。 Mainの**Side chat**をラベルしたメッセージをチェックしてください。 Main がアイドルの場合、次のリクエストを送信して作業を続行してください。
4. **Cancel Side chat response** を使用して、現在の回答を停止します。 後で読み返すには、タブを開いたまま別のタブに切り替えるか、プレビュー領域を折りたたんでください。

テキストや注釈を含むドラフトは、ビューを切り替えるのに役立ちます。 退去時に不接触の空の草案が破棄されます。 ドラフトだけを開くと、モデルリクエストは送信されません。

### 注釈を適切な下書きに移動する {/* #move-an-annotation-to-the-right-draft */}

選択された通路や地域のために、アノテーションの**Move to Side chat…**アクションを使用し、既存の側面の議論や新しいものを選択します。 MainとSide Chatのドラフトのアノテーションをドラッグすることもできます。 送信する前に、宛先と転送されたコンテンツをチェックしてください。注釈を移動すると、ドラフトが準備されます。 リクエストを送信しません。

プライベート**For me**ブックマークは異なる読書ツールです。 [読書ブックマーク](bookmarks.md) を参照してください。

### 注意点 {/* #things-to-know */}

- **モデル設定：** 新しいSide Chatは、現在のメインの会話モデルと推論の努力を継承しています。 Side Chatで変更できます。 選択は、次の送信に適用されます。 Codex サブスクリプションがサポートされています。 送信前にセレクターをチェックしてください。
- **送信と操作：** 通常応答はMainに自動的に送られません。 Side ChatはMainの許可を付与できません。 Main を依頼する前に、配信確認をします。
- **タブを閉じる場合：** 確認する前に **Close Side chat?** を読んで下さい。 タブを閉じると、その Side Chat が停止し、保存された会話が完全に削除されます。 **Cancel** を選択して、Main または保存されたレポートに便利なアドバイスを転送します。 クリーンアップが失敗した場合、タブは戻ります。 再試行する前にエラーを調べます。
- **利用条件：** v0.30.2 では、Main が実行中または承認待ちであることだけを理由に Side Chat が無効になることはありません。まず Main で少なくとも一度メッセージを送信してください。読み取り専用のインポート済みセッションや、利用できない親セッションでは開けません。送信には履歴の保存と復元も必要です。Side Chat はファイル添付に対応していません。ボタンの説明を確認し、接続の問題は[トラブルシューティング](troubleshooting.md)を参照してください。

## タスクの委派 {/* #task-delegation */}

### 利用場面 {/* #when-to-use-it-1 */}

文献のソースをチェックしたり、データファイルをチェックしたり、分析結果をレビューしたりするなど、独立して処理できる作業を委任し、メインエージェントが調査結果を結合させます。 定義された役割を持つ再使用可能なアシスタントについては、[Specialistの代表団](../specialists/delegate.md) を参照してください。

### 使い方 {/* #how-to-use-it-1 */}

1. Composer's **Agent controls** で **Delegation** をチェックします。
2. **Settings → Model → Subagent**では、メインモデルから継承するか、互換のモデルと推論の努力を構成します。
3. 要求の入力ファイル、予想される出力および受諾の基準を委任するタスクを記述して下さい。
4. サブタスクのステータスをアクティビティエントリでフォローし、任意の許可リクエストに応答します。
5. 返されたファイルまたはソースリンクを開き、結果を確認します。 実行レコードを検査するには、Notebook の **Agent** フィルターで対応する所有者を選択します。

### 注意点 {/* #things-to-know-1 */}

- 利用可能な機能は、エージェントフレームワークと構成に依存します。 Delegationを有効にした後、アクティビティエントリをチェックして、サブタスクが実際に起動していることを確認します。
- サブエージェントは、Main のコンテキストまたは Python 変数の全てをシェアすることはできません。 タスクに必要なファイルや指示を供給します。
- Mainのプラン承認は、すべてのサブエージェントアクションを自動的に承認しません。 許可が要求される場合、特定のアクションとスコープを確認してください。
- **Release** が利用可能になったら、サブタスクリソースを終了するか、または解放するために使用します。 Mainの証拠は保持されます。
