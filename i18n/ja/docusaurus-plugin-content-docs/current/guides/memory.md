# 記憶と会話のコンテキスト {/* #memory-and-conversation-context */}

記憶店の再使用可能なノート; コンテクストウィンドウは、特定のモデルリクエストに利用できる材料です。 保存されたメモは、エージェントがそれをリコールする証拠ではなく、可視された古いメッセージは、元の履歴全体が次のリクエストに収まるという証拠ではありません。

生数を保存したり、遺伝子を試料数から分離したりするなど、耐久性のある規則のカテゴリを使用します。 新しいリクエストに提供された規約を望むときに、メモリとカテゴリのオートリコールを有効にします。

## カテゴリとノートを作成する {/* #create-a-category-and-note */}

<p className="example-label"><strong>実践例</strong> RNA-seq レポートの規約を保存し、リコールする</p>

1. **Settings → Memory → New category** を開きます。
2. `RNA-seq methods` を **Name** に入力します。 **When should the agent save a note here?**では、このカテゴリに確認されたメソッドが属しているときに記述します。
3. **Auto-recall**を意図的に設定します。 この例では、手動で維持されたメソッドのメモを省略します。
4. **Create** を選択し、**Add** を選択します。 ノートを入力し、**Save**を選択します。
5. コンテンツとカウントを検証するためにカテゴリを離れ、再開します。

![カテゴリー名、案内、オートリコール](/img/open-science/guides-walkthrough/17-memory-category.png)

保存されたノートは「元の GEO カウント行列を変更しない」と読みます。 Entrez Gene IDをテキストとして保存し、遺伝子の長さをサンプルカウントから分離し、すべての派生テーブルで入力 SHA-256 を記録します。これは、分析結果に関する主張ではなく、作業慣行です。

![記憶が消えている間手動で保存されたノート](/img/open-science/guides-walkthrough/18-memory-note.png)

| コントロール | 効果と境界 |
| --- | --- |
| 記憶スイッチ | 有効/無効なエージェントの保存とリコール。 オフは既存のメモを保持し、手動編集を可能にします。 |
| カテゴリ行 | そのカテゴリのメモとカウントを表示します。 カテゴリー グループ関連のメモリをプロジェクト全体に関連付けます。 |
| プロジェクトビュー | プロジェクトスコープのメモを表示 グローバルなカテゴリから区別します。 |
| 新しいカテゴリ | 64 文字までの名前、1,000 までのガイダンス。 10のカスタムカテゴリの最大値。 |
| Add / メモリノート | 4,000 文字までのメモを作成します。 空のテキストは、未利用可能な保存を保存します。 |
| メモをコピー | テキストをコピーします。 |
| メモの編集 → 保存/キャンセル | パーシストは、編集するテキストまたは廃棄を修正しました。 |
| カテゴリーのアクション → 編集 | カスタムカテゴリの名前、ガイダンス、オートリコールを変更します。 |
| カテゴリー アクション → オートリコール | このカテゴリの自動包含を制御する。 メインメモリスイッチは適用されます。 |

**About you**は組み込みのカテゴリです。 そのアイデンティティは、カスタムカテゴリのように編集または削除することはできません。

## 会話からコンベンションを保存 {/* #save-a-convention-from-a-conversation */}

1. **Settings → Memory → Memory**をオンにします。 **RNA-seq methods → Category actions** を開き、**Auto-recall** を有効にします。
2. プロジェクトの会話では、エージェントが確認された慣習を記憶し、カテゴリを名前付けるように依頼してください。 例えば、「RNA-seq」メソッドで覚えています。GSE60450記述QCでは、検出された遺伝子とは別にゼロカウント遺伝子を報告します。 2つのカウントは、各サンプルの27,179に合計する必要があります。
3. 承認が必要な場合は、**Save memory**リクエストを調べます。 **Allow once**を選択する前に、提案されたコンテンツ、カテゴリ、およびプロジェクトスコープを確認してください。 合意された慣習を表さない場合は、**Deny** を選択します。
4. カテゴリを再オープンします。 ノートが存在することを確認し、意図したテキストを持ち、意図したプロジェクトの下に表示されます。 **auto** ラベルはエージェント作成ノートを識別します。 条約が検証された計算は意味しません。

![マニュアルのソース保存ノートと一緒にエージェント作成の報告規則](/img/open-science/non-workflow-completion/05-memory-note-category.png)

## 新しい会話でリコールをチェックする {/* #check-recall-in-a-new-conversation */}

**同じプロジェクトで新しい会話**を起動し、回答をすることなく、レポートの規約を保存したかを尋ねます。 応答をメモと比較します。 元の会話の質問は、既存の歴史から回答することができます。

メインの**Memory**スイッチをオフにし、別の新しい会話で質問を繰り返す. エージェントがアプリケーションメモリを介してノートを受信しなくなったことを確認します。 保存されたメモは、設定に残ります。 メモリオフの切り替えは、既存の会話に既に存在するメモを消去したり、テキストを削除したりしません。

上記の保存は、明示的な「記憶」要求に従います。 エージェントは、すべての有用な慣習を自発的に識別するというわけではありません。 コンテクストの圧縮はメモリノートを保存することで分離されます。

## 会話のコンテキストを調べる {/* #inspect-conversation-context */}

セッションでは、**使用されるコンテキスト** パーセンテージまたは **Add menu → Context window** を使用可能に開いてください。 **Current composition**、**History**、**Session call summary** を調べます。 カテゴリーには、システムプロンプト、ツール、エージェント、メッセージ、コネクタ、MCP、Skills、フレームワークオーバーヘッドを含めることができます。

実行、モデル、占有率、ターミナルの状態を調べる履歴ポイントを選択します。 現地見積りと提供者報告された測定は異なります。 利用できないカテゴリの詳細は利用できません。 圧縮マーカーは、すべての表示されたメッセージの新しい保存されたアーティファクトや削除ではなく、コンテキストイベントを記録します。 手動圧縮制御は、アクティブなフレームワークに依存します。

OpenCode がコンテキストポップアップで **Compact** を提供したら、それを選択して **Context compacted** を待ちます。 バックエンドがサマリーから続く間、元のメッセージは表示され続けることができます。 続行する前に、エージェントは保持された制約をリストし、要件とそれらを比較するように依頼します。 次の操作を開始する前に、欠落または誤った制約を再ステートします。 コンパクト化は、損失のない保持を保証するものではありません。 提供者の測定は、現地見積と異なることができます。

![完全コンパクト化とプロバイダが報告したコンテキスト測定](/img/open-science/non-workflow-completion/11-context-compacted.png)

継続のために、現在の目標、承認された決定、正確な入力/出力ファイル、検証は既に完了し、未解決の質問を述べます。 保存された証拠を、メモリに依存して再構築するのではなくリンクします。 [セッションとブランチ](./sessions.md) は、分岐/エクスポートおよび [使用量](./usage.md) で、累積トークンのボリュームに使用します。

## 意図したスコープだけを削除 {/* #delete-only-the-intended-scope */}

**Delete note** は、確認後に 1 つのノートを削除します。 **Delete category**はカテゴリとそのノートを削除します。 影響を受ける数を調べます。 **Clear all** は、カスタムのカテゴリとメモを削除し、あなたのことについて保持します。 スコープが意図よりも大きい場合はキャンセルします。 古いバックアップは削除されたメモを含むことができます。
