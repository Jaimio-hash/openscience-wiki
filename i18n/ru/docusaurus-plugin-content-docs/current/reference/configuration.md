# Конфигурация и контекст {/* #configuration-and-context */}

Эта ссылка разделяет контекст проекта, дефолты новой сессии и конфигурацию существующей сессии. Используйте [Проекты](../guides/projects.md) или [Настройка поставщика](../guides/providers.md) для прохождения соответствующего интерфейса.

## Контекст и право собственности на конфигурацию {/* #context-and-configuration-ownership */}

| Значение | Владелец и эффект | Не заменяет |
| --- | --- | --- |
| Проект **Name** | Имя дисплея проекта, требуемое, максимум символов 200 | Уникальный проект ID |
| Проект **Description** | Описание проекта-списка, максимум символов 1,000; не включен в состав агента по запросу | Инструкция агента |
| Проект **Agent Context** | Максимум символов 16,000; включенные в новые и возобновленные сессии проекта и направленные поставщику моделей; | Полномочия или выполненный запрос задачи |
| Сессия **Title** | Заголовок дисплея, максимум символов 80 | Контекст проекта или идентификатор филиала |
| Сессия **Description** | Организационное описание, максимум символов 1,000 | Новое пользовательское сообщение |
| Поставщик моделей | Подключение, учетная запись и настроенный каталог моделей | Установка агент-фреймворка |
| Фреймворк агента | Runtime используется для выполнения задачи | Переводчик Notebook |
| Python/R Runtime | Переводчик, используемый для выполнения Notebook | Модель или ее настройка аргументации |
| Память | Сохраненные заметки с собственным объемом и контролем отзыва | Полная история разговоров |
| Навык | Инструкции и файлы многоразового метода | уже установленная зависимость или предоставленные служебные полномочия |

## Продвинутая: конфигурация API {/* #advanced-task-api-configuration */}

### Новые сессии, созданные с помощью задачи API {/* #new-sessions-created-through-the-task-api */}

Задача бегуна решает каждое поле отдельно. Следующий приоритет относится к сессии **новый** Task API, а не ко всем существующим разговорам на рабочем столе.

| Полное поле | Резолюция, высший приоритет |
| --- | --- |
| Профиль разрешений | Явный запрос запуска → дефолты сессии проекта → дефолт приложения `ask` |
| Автопроверка | Явный запрос → Дефолт проекта `false` |
| Память включена | Явный запрос → Дефолт проекта `true` |
| Политика делегирования | Явный запрос → Дефолт проекта `allow` |
| Специалист | Явный запрос - проект по умолчанию, когда установлен |
| Провайдер/модель/обоснование | Явный патч конфигурации по сравнению с конфигурацией проекта или эффективной конфигурацией приложения / поставщика |
| Выбранные вычислительные хосты | Явные выбранные идентификаторы → выбранные идентификаторы проекта |

Включенные вычислительные хосты также включают выбранные идентификаторы во время подготовки к новой сессии. Явно пустой список включенных хостов очищает унаследованный список включенных перед включением выбранных хостов. Для обновления конфигурации существующей сессии каждый выбранный идентификатор должен присутствовать в включенном наборе.

Используйте ссылку [CLI](cli.md) или [Задание SDK/API](api.md) для фактических команд чтения/обновления. Дефолты сеанса проекта – это контракт на конфигурацию; Не думайте, что диалог «Название/Описание» раскрывает все эти области.

### Принятые значения конфигурации {/* #accepted-configuration-values */}

| Полное поле | Принятая стоимость |
| --- | --- |
| `agentConfiguration.providerId` | Непустой сконфигурированный идентификатор провайдера |
| `agentConfiguration.model` | Факультативный идентификатор модели; Патч обновления может использовать `null` Перезагрузка по умолчанию для провайдера |
| `agentConfiguration.reasoningEffort` | `default`, `low`, `medium`, `high`, `xhigh`, `max`; Фактическая возможность выбора зависит от поставщика/модели. |
| `permissionProfile` | `ask`, `auto`, `full` |
| `autoReviewEnabled` | булевый |
| `memoryEnabled` | булевый |
| `delegationPolicy` | `allow`, `deny` |
| `specialistId` в проектных дефолтах | незаполненный ID; Не поле в обычном патче конфигурации сессии |
| `computeHosts.enabled`, `.selected` | массивы непустых идентификаторов хоста; Выбранное должно быть подмножеством включенного |

Схемы отвергают неизвестные поля. Наличие отображаемой модели не гарантирует, что ее можно выбрать с помощью текущей структуры или учетных данных. Используйте настроенный каталог и результат доступности.

### Дефолты провайдера и недоступные конфигурации {/* #provider-defaults-and-unavailable-configurations */}

Для провайдера подписки, оставляя модель неуказанной, сохраняется учетная запись / CLI, принадлежащая по умолчанию. Он не прикрепляет первую модель, указанную в каталоге. Если сохраненная конфигурация сеанса больше не поддается выбору, то разрешитель рендерера может использовать активную выбираемую конфигурацию приложения; Если ни один из них не доступен, он сообщает о недоступности. Осмотрите выбранную модель при повторном открытии старых работ после смены провайдеров.

### Обновление и возобновление правил {/* #update-and-resume-rules */}

Прочитайте текущую конфигурацию существующей сессии перед ее редактированием. Включите в обновление **`expectedRevision`**, неотрицательное целое число. Сервер отклоняет устаревшую версию `session_revision_conflict`. Он также отклоняет обновления, пока сеанс работает или находится в состоянии бездействия / ошибки.

Для изменения поставщика требуется либо явная модель, либо `model: null`, чтобы выбрать новый поставщик по умолчанию. Отказ от модели при смене провайдера не несет в себе модель старого провайдера. Сброс модели отличается от пустой строки.

Чтобы изменить провайдера, модель, аргументацию, память или включенные вычислительные хосты перед возобновлением существующей сессии Task API, сначала используйте операцию обновления конфигурации сессии. Поставка этих полей времени создания в запросе резюме возвращает `invalid_request`. Рабочий каталог должен соответствовать каноническому каталогу сессии.

Обновления по умолчанию проекта используют **`expectedUpdatedAt`**, положительную целочисленную временную метку из текущего проекта и патч. Поле по умолчанию проекта `null` удаляет эту оверрайд; Опускание поля сохраняет его. Обновление по умолчанию регулирует создание будущих сессий и не переписывает существующие выходные данные.

## Инструкции хоста и выбор секретного хранилища {/* #host-instructions-and-secret-storage-choices */}

Инструкции сохраненного вычислительного хоста и обнаруженные ресурсы разделены. Пустой сохраненный документ инструкции отличается от успешного исследования ресурсов. Агент-ассистированная замена должна использовать текущий сохраненный текст в качестве защиты. См. [Хостинговые детали](../guides/remote-compute.md#keep-host-instructions-separate-from-detected-resources); Этот внутренний контракт отделен от публичной задачи API.

Credential storage — это выбор стартапа, а не предпочтение проекта или сессии. См. [Файловый режим Linux](server.md#credential-storage-on-headless-linux) для области, OS-магазина по умолчанию и ограничения миграции. Не размещайте флаг магазина учетных данных в конфигурации сеанса JSON.
