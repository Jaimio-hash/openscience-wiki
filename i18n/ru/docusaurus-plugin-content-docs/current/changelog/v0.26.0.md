# Changelog - v0.26.0 {/* #changelog--v0260 */}

Open-Science [v0.26.0](https://github.com/aipoch/open-science/releases/tag/v0.26.0) включает в себя следующие изменения, связанные с пользователем. Для текущих инструкций по эксплуатации следуйте связанным руководствам по функциям.

## Рабочие процессы Main {/* #main-workflows */}

### Литературная справочная библиотека {/* #literature-reference-library */}

Новая локальная справочная библиотека импортирует отдельные PDF-файлы и записи BibTeX, RIS или NBIB. организует ссылки в сборники и проекты; Найти дубликаты; прикрепляет выбранные PDF-файлы с открытым доступом; и форматы цитирования с провенансом ревизии. Обнаруженные агентом ссылки вводят в почтовый ящик вместо того, чтобы молча присоединяться к библиотеке. Смотрите [Библиотека литературы](../guides/library.md).

### Выполнение Slurm для удаленных вычислений {/* #slurm-execution-for-remote-compute */}

Каждый хост SSH теперь имеет **Execution mode**: **Direct SSH** или **Slurm**. Режим Slurm отправляет задания, принадлежащие планировщику, проводит опросы о долговечном состоянии, восстанавливается после перерыва, отменяет через планировщик и очищает постановочные файлы. Встроенный навык **Настройка вычислительной среды** дает инструкции по настройке, ремонту и удалению для выбранного хоста. Просмотрите их самостоятельно или отправьте администратору кластера.

![Режим удаленного хоста](/img/open-science/v0.26.0/compute-slurm-mode.png)

Не выберите Slurm только потому, что `sbatch` существует. Подтвердите политику хоста входа в систему, по умолчанию раздел / учетная запись / QoS, путь царапин, настройку модуля или среды, ограничения по времени стен и правила отмены. Open-Science не предоставляет доступ к кластеру или планировщику.

### Считываемый инструмент и карточки одобрения {/* #readable-tool-and-approval-cards */}

Артефакт пишет, а обычные элементы управления ноутбуком отображаются как компактные сводные карты вместо сырых JSON. Расширяйте карту, когда имеют значение точные аргументы, пути, версии или состояние исполнения. Карты утверждения Skill могут расширить весь `SKILL.md` до принятия решения.

![Расширенный документ Skill в утверждении](/img/open-science/v0.26.0/skill-approval-expanded.png)

### Поставщики и модельные каталоги {/* #providers-and-model-catalogs */}

Apodex доступен как встроенный провайдер с `apodex-1.1` и `apodex-1.1-mini`. В комплект каталогов также входят GPT-6 Astra и Claude Fable 5.1 с поддержкой управления рассуждениями. Каталог не предоставляет учетные данные, доступ или емкость; Установленный пикер и успешный тест на подключение являются авторитетными.

## Другие изменения, видимые пользователем {/* #other-user-visible-changes */}

- Обычная проверка ноутбука / рабочего времени только для чтения **Разрешения:**, поиск памяти, инвентаризация пакетов и утвержденные обновления плана имеют более безопасные гранты по умолчанию. Гранты остаются видимыми и отзывными в настройках.
- **Меню предварительного просмотра:** нажимает правой кнопкой мыши на предварительный просмотр контента, чтобы скопировать путь, загрузить или сохранить локальный файл в качестве артефакта. Управляемые артефакты могут обнажать происхождение и возврат к контексту.
- Клиенты **Задание API:** CLI, HTTP и SDK могут проверять или обновлять модель сеанса, усилия по рассуждению, настройку памяти и выбор вычислительного хоста без отправки запроса.
- Импорт **Большой Skills:**, содержащий десятки тысяч файлов, использует ограниченный, более быстрый путь и сохраняет проверки целостности пакета.
- Потоковая передача **Надежность:**, использование ресурсов на длительной сессии, восстановление плана, обработка обновлений, время выполнения ноутбуков, публикация артефактов, настойчивость, состояние поставщика, учетные данные, удаленный доступ, миграция хранилища и доступность получили исправления восстановления и правильности.

## Обновление задачи SDK {/* #breaking-task-sdk-change */}

Наследие сессионно-плановых полей было удалено из публичного контракта Task SDK. Клиенты должны прочитать текущую сессию и планировать состояние через поддерживаемые API. Тестовые интеграции, которые десериализируют старые поля перед обновлением; Это изменение затрагивает потребителей API, а не обычные настольные разговоры.
