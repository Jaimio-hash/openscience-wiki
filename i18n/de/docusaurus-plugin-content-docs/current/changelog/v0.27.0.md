# Changelog · v0.27.0 {/* #changelog--v0270 */}

Diese Veröffentlichung erweitert den Literaturimport, fügt Hintergrundausführung hinzu und verbessert die Wiederherstellung über Forschungssitzungen hinweg. Es hält auch die anwendungsbedingte Skills aktiviert und fügt Connector-Verwaltung für CLI- und SDK-Benutzer hinzu.

[Offizielle Freigabe](https://github.com/aipoch/open-science/releases/tag/v0.27.0) · [Änderungen seit v0.26.0](https://github.com/aipoch/open-science/compare/v0.26.0...v0.27.0)

## Neue Features {/* #new-features */}

### Mehrere PDFs zusammen importieren {/* #import-several-pdfs-together */}

Durch die Auswahl mehrerer PDFs wird ein Importdialog mit Dateiauswahl, einer Zielzusammenfassung, einer Identifier-Match-Richtlinie, Fortschritt und Ergebnissen pro Datei geöffnet. **Stop** beendet die weitere Verarbeitung; **Retry unfinished** nimmt unvollendete Auswahlen wieder auf. Durch die Auswahl eines einzelnen PDF bleibt die Metadaten-Editor-Route erhalten.

Wählen Sie aus, ob Sie eine übereinstimmende Referenz wiederverwenden, einen separaten Datensatz beibehalten oder leere Felder ausfüllen möchten. Die Bibliothek zeigt auch ihre aktive Summe unabhängig von Suchfiltern an und kann Metadaten aus einem erkannten DOI anreichern. Überprüfen Sie den extrahierten Titel und die Identifikatoren: Ein abgeschlossener Import garantiert keine korrekten Metadaten. Siehe [Literaturbibliothek und Zitate](../guides/library.md).

![Batch PDF-Import mit zwei PRISMA-Papieren](/img/open-science/v0.27.0/02-pdf-batch-ready.webp)

### Arbeiten Sie weiter, während Aufgaben ausgeführt werden {/* #continue-working-while-tasks-run */}

Unterstützte Python, R, persistente REPL- und Shell-Arbeiten können im Hintergrund ausgeführt werden. Die Sitzung verfolgt die Aufgabenidentität, den Status, die verstrichene Zeit und die Stornierung; **Open** kehrt zum entsprechenden Lauf zurück. Ergebnisse können automatisch an die Konversation für lokale Runs und Remote Compute-Aufträge geliefert werden.

Überprüfen Sie die gespeicherten Dateien nach Abschluss. Remote-Jobs erfordern weiterhin einen konfigurierten Host und geeignete Ressourcen. Siehe [Hintergrundaufgaben](../guides/notebook.md#background-tasks-and-result-delivery).

![Abgeschlossene lokale Hintergrundaufgabe](/img/open-science/v0.27.0/13-background-task-completed.webp)

### Halten Sie die Anwendung Skills verfügbar {/* #keep-application-skills-available */}

**Customize**, **Umwelt & Pakete**, **Remote Compute (SSH)** und **Einrichtung einer Comput-Umgebung** bleiben nun aktiviert. Ihre überprüften, deaktivierten Schalter erklären, warum sie nicht ausgeschaltet werden können. Interne Unterstützung Skills bleibt ebenfalls verfügbar; Sie sind keine zusätzlichen öffentlichen methoden im verzeichnis.

Dadurch werden keine wissenschaftlichen Abhängigkeiten installiert oder der Zugriff auf ein Specialist gewährt. Siehe [Erforderlich Skills](../skills/overview.md#why-some-switches-cannot-be-turned-off) und [Erstellen Sie ein Skill](../skills/create.md) für den Workflow Speichern als Fertigkeit.

### Verwalten von Integrationen aus Skripten {/* #manage-integrations-from-scripts */}

CLI und Task SDK fügen Connector-Erkennungs-, Inspektions- und Aktivierungs-/Deaktivierungskontrollen neben dem benutzerdefinierten Connector-Management hinzu. Headless Linux erhält auch eine explizite dateibasierte Berechtigungsnachweis-Speicheroption, wenn ein OS-Berechtigungsnachweis-Tresor nicht verfügbar ist; Der OS-Speicher bleibt standardmäßig. Der Dateispeicher ist unverschlüsselt und muss durch Filesystem-Zugriffskontrollen geschützt werden.

Siehe [Connector CLI Befehle](../reference/cli.md#manage-connectors-and-credentials), [SDK-Verfahren](../reference/api.md#connector-management-methods) und [Linux Credential Storage](../reference/server.md#credential-storage-on-headless-linux).

## Kompatibilität und bekannte Probleme {/* #compatibility-and-known-issues */}

Die Version enthält [#2394](https://github.com/aipoch/open-science/pull/2394), das das Codex-Abonnement Side Chat Startup und Resumee im Backend behebt. Derselbe tagged Desktop-Code behält einen Provider-Schutz, der seinen Menüeintrag deaktiviert; Eine neue Überprüfung dieses quellengebauten desktops erreichte diesen wachmann immer noch. Verfolgen Sie dies als eine UI / Backend-Diskrepanz, die eine Untersuchung und eine End-to-End-Überprüfung erfordert, und nicht als absichtlichen Mangel an Unterstützung. Siehe [Side Chat Verfügbarkeit](../guides/delegation.md).

Dieser Desktop-Eingangsschutz wurde in [v0.29.0](./v0.29.0.md) entfernt; die oben beschriebene Einschränkung gehört zur v0.27.0-Quelle.

Für die Installation oder Updates siehe [Installieren und Update](../guides/installation.md). Frühere Änderungen bleiben in [v0.26.0](./v0.26.0.md).
