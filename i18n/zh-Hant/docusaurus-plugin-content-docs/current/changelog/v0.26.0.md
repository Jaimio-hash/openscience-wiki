# 更新日誌 · v0.26.0 {/* #更新日志--v0260 */}

Open-Science [v0.26.0](https://github.com/aipoch/open-science/releases/tag/v0.26.0) 包含以下使用者功能更新。當前操作方法以連結的功能教程為準。

## 主要工作流 {/* #主要工作流 */}

### 文獻資料庫 {/* #文献资料库 */}

新的本地資料庫可匯入單個 PDF 以及 BibTeX、RIS、NBIB 記錄；可用集合和專案整理文獻、檢查重複項、附加選定的開放獲取 PDF，並生成帶修訂來源的引用。智慧體發現的文獻會先進入 Inbox，不會靜默加入資料庫。詳見[文獻資料庫](../guides/library.md)。

### 遠端計算的 Slurm 執行模式 {/* #远程计算的-slurm-执行模式 */}

每個 SSH 主機新增 **Execution mode**：**Direct SSH** 或 **Slurm**。Slurm 模式會提交由排程器管理的 job、輪詢持久狀態、在中斷後恢復、透過排程器取消並清理 staging 檔案。內建 **Compute Environment Setup** skill 會為所選主機生成安裝、修復與移除說明；應自行復核，或交給叢集管理員稽核。

![遠端主機執行模式](/img/open-science/v0.26.0/compute-slurm-mode.webp)

不要因為主機上存在 `sbatch` 就直接選擇 Slurm。先確認登入節點規則、partition/account/QoS 預設值、scratch 路徑、module/環境準備、wall time 限制和取消規則。Open-Science 不負責配置叢集或授予排程權限。

### 更易讀的工具與授權卡片 {/* #更易读的工具与授权卡片 */}

Artifact 寫入和常用 Notebook 控制會顯示緊湊摘要卡片，而不是直接展示 raw JSON。路徑、版本、引數或執行狀態很重要時仍應展開詳情。Skill-load approval 可在決定前展開完整 `SKILL.md`。

![授權卡片中展開的 Skill 文件](/img/open-science/v0.26.0/skill-approval-expanded.webp)

### Provider 與模型目錄 {/* #provider-与模型目录 */}

Apodex 成為內建 provider，包含 `apodex-1.1` 和 `apodex-1.1-mini`。內建目錄還加入支援相應 reasoning 控制元件的 GPT-6 Astra 與 Claude Fable 5.1。目錄存在不代表已有憑據、訪問資格或容量；應以已安裝版本的 picker 和成功的 connection test 為準。

## 其他使用者可見變化 {/* #其他用户可见变化 */}

- **Permissions**：常規只讀 Notebook/runtime 檢查、Memory 查詢、包清單和已批准計劃的進度更新擁有更安全的預設 grant；仍可在 Settings 檢視並撤銷。
- **Preview 選單**：在預覽內容中右鍵，可複製路徑、下載或把本地檔案儲存為 artifact；託管 artifact 可提供 provenance 和返回來源上下文。
- **Task API**：CLI、HTTP 和 SDK 客戶端無需傳送 prompt，就能讀取或更新會話的模型、reasoning effort、Memory 設定和計算主機選擇。
- **大型 Skill**：包含數萬檔案的包採用受限的高速匯入路徑，並保留完整性檢查。
- **可靠性**：streaming、長會話資源佔用、計劃恢復、更新處理、Notebook runtime、artifact 釋出、持久化、provider 狀態、credential、remote access、儲存遷移與無障礙均有恢復和正確性修復。

## Task SDK 破壞性變更 {/* #task-sdk-破坏性变更 */}

公開 Task SDK 合約已移除舊版 session-plan continuation 欄位。客戶端必須透過當前受支援的 session/plan API 讀取狀態。升級前應測試仍反序列化舊欄位的整合；普通桌面對話不受影響。
